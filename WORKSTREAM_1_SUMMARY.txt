================================================================================
WHY YOU SEE "STUB DATA" IN THE DEMO
================================================================================

SEC EDGAR requires a REAL EMAIL ADDRESS in the User-Agent. The default uses
"sample@example.com" which SEC rejects with 403 Forbidden.

This is NOT a code bug - it's a required configuration step!

================================================================================
HOW TO GET LIVE DATA (2 MINUTES)
================================================================================

Step 1: Set your email in the User-Agent (SEC requirement)
   
   PowerShell (Windows):
   $env:SEC_USER_AGENT = "YourCompany/1.0 (your.email@example.com)"
   
   Bash (Linux/Mac):
   export SEC_USER_AGENT="YourCompany/1.0 (your.email@example.com)"
   
   IMPORTANT: Replace "your.email@example.com" with YOUR ACTUAL EMAIL!
   SEC uses this to contact you if there are issues with your usage.

Step 2: Enable live data

   $env:BENCHMARKER_USE_LIVE = "1"
   $env:BENCHMARKER_DATA_SOURCE = "edgar"

Step 3: Test it

   py demo_live_data.py
   
   You should see:
   [OK] CONFIRMED: Using live SEC EDGAR data!

Step 4: Run your pipeline

   py -m signal_triage.cli your_document.pdf --pipeline
